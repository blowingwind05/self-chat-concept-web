一个只和自己聊天的 App。一个纯粹而且足够好用的文件传输助手。项目构想展示。

短片文字稿 阅读原案叙事

我现在经常使用微信的文件传输助手，或者直接给自己的 QQ 账号发消息。灵感、学习工作中的记录、文案和稿件、喜欢的作品，都会顺手发进去。想到什么直接发条消息，总比新建文档、考虑怎么分类方便得多。

但是我经常需要在 Mac、Windows 和 Linux 之间传文件，我用微信、QQ 时，同一账号只能同时登录一台电脑，只能来回切换。微信里的记录要自己保留、备份和迁移；QQ 的云端漫游也有期限和内容范围。即使是飞书，免费版也只能查看最近 18 个月的记录。我也希望所有消息和文件都能长期保存在云端，换了设备还能找回完整的历史记录。消息多了难免杂乱，正好可以交给 AI 帮忙整理。

多种用途，一个聊天入口。不需要提前分类，直接发送。灵感创意、学习工作、文案与稿件、审美积累、书影音清单、生活回顾、待办与日程、网页收藏、文件传输，都先作为普通消息进入同一条时间线。

原案例子：想看《布达佩斯大饭店》；明早给老师发邮件；各位老师好，我今天汇报的题目是……首先介绍一下课题的研究背景……；讲稿_v3.pdf；黑白建筑摄影；想补《冰菓》；serendipity，偶然发现美好事物的机缘；今天终于把实验跑通了；project-files.zip。

云端负责长期保存消息与附件，AI 负责理解和整理。整理结果单独保存，可以修改、纠正或重新生成，不影响原始消息。整理后的内容包括书单影单番单、待办与提醒、审美素材库、学习与笔记、生活回顾和智能检索。

计划支持六平台客户端和多设备同时登录，初期支持自托管部署。五个开发阶段分别是基础消息系统与自托管、AI 整理与归纳、六平台客户端与个人信息管理、长期可靠性与安全体系研究、公开测试与官方托管。阶段顺序不代表重要性的排序；基础安全从第一阶段开始。

初期应考虑安全身份认证、HTTPS 传输加密、数据访问控制、设备与会话管理、备份恢复和基本限流与防护。第一版应具备与实际使用范围相匹配的基本安全措施，但不将早期自托管版本描述为经过全面安全审计的成熟产品。

AI 整理需要读取消息、文档和图片，因此数据存储与模型处理应在架构上区分。初期考虑可配置模型 API，未来也可以支持自托管模型。用户应知道哪些数据送往外部服务，并控制处理范围。端到端加密、服务端搜索、AI 整理与账号恢复之间的关系仍需研究。现阶段不提前承诺端到端加密或零知识存储，也不将 HTTPS 等同于服务器无法读取内容。

后续研究包括多因素身份验证、多设备信任机制、数据加密与密钥管理、账号与数据恢复、安全测试与漏洞审查、多用户隔离与滥用防护。具体安全模型尚未确定，需在公开测试或官方托管前完成相应验证。

技术栈尚未完全确定。初步考虑 Go、PostgreSQL、SQLite、本地或 S3 兼容文件存储、HTTP API 与增量同步，按需加入 WebSocket；优先支持 Docker Compose。消息和附件先可靠保存，再由独立任务进行 AI 处理。只有服务端持久化确认后，才标记为已保存到云端；附件也需要完整性校验。

最后想做成的样子，是一个真正能长期用下去的文件传输助手。目前仍处于项目构想阶段，具体功能、技术方案与开发顺序都有调整空间。标题是在说明这个想法是什么，项目尚未命名。
